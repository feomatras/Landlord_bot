ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) – ВЕРСИЯ 2.2 (ФИНАЛ)

На разработку Telegram-бота для автоматизации расчёта коммунальных платежей

Дата: 16.08.2026
Статус: Утверждено к разработке
Среда реализации: Python + библиотека python-telegram-bot (v20+), база данных SQLite, планировщик APScheduler. Хостинг – бесплатный облачный сервис (рекомендуется Render.com) для круглосуточной работы.

---

1. Цели и бизнес-ценность

Цель: Полностью автоматизировать ежемесячный сбор показаний счётчиков от арендатора (до 25-го числа месяца), расчёт коммунальных платежей с учётом индивидуальных тарифов для каждой квартиры (включая ступенчатый тариф на электричество), формирование отчёта администратору и контроль оплаты (до 10-го числа следующего месяца) с автоматическими напоминаниями.

Бизнес-ценность:

· Экономия времени администратора (отсутствие ручных напоминаний, проверок и расчётов).
· Исключение ошибок в вычислениях.
· Прозрачность для арендатора (видит полную разбивку).
· Возможность масштабирования на несколько квартир с разными тарифами.
· Контроль оплат через историю с чек-боксами и автоматические напоминания об оплате.

---

2. Роли пользователей

Роль Описание Действия
Администратор Собственник (вы) Управляет квартирами, пользователями, тарифами, вносит суммы УК и капремонта, загружает квитанции, отмечает оплаты, просматривает историю, получает напоминания об оплате
Арендатор Жилец квартиры Получает напоминания о передаче показаний (23-го числа), вводит показания счётчиков (до 25-го), видит итоговую сумму и уведомления о появлении УК, получает квитанции

3. Функциональные требования

3.1. Регистрация и безопасность (доступ по приглашению)

· Бот работает только с пользователями, добавленными администратором в белый список.
· Каждый пользователь привязан к конкретной квартире (flat_id) и роли (admin или tenant).
· Команды администратора для управления доступом:
  · /adduser <TelegramID> <роль> <номер_квартиры> – добавить пользователя.
  · /removeuser <TelegramID> – удалить пользователя.
  · /listusers – показать всех пользователей с их ролями и квартирами.
· При первом запуске бот автоматически назначает администратором того, кто отправил /start (с проверкой по секретному ключу, например, запросив код при первом старте). Рекомендуется использовать простой пароль, известный только владельцу.

3.2. Управление квартирами и тарифами (интерфейс с кнопками)

Создание новой квартиры:

· Администратор вводит команду /addflat <название> (например, /addflat Квартира 1).
· Бот создаёт запись в таблице flats с уникальным id и присваивает тарифы по умолчанию (все = 0.0, для электричества пороги = 150 и 800, тарифы = 0.0).
· Далее администратор должен настроить тарифы через меню.

Выбор активной квартиры:

· Команда /select_flat <номер> – администратор переключает активную квартиру. Все последующие настройки применяются к ней.
· Если администратор отправляет /select_flat без номера, бот показывает список всех квартир с номерами и названиями.

Главное меню администратора (после /start или /menu):

· Отображает текущую выбранную квартиру и её тарифы (включая ступенчатый тариф на электричество).
· Кнопки для изменения каждого тарифа:
  · «Изменить тариф Воды»
  · «Изменить тариф Электричества» (открывает специальный диалог для ввода ступенчатых значений)
  · «Изменить тариф Газа»
  · «Изменить ТКО»
  · «Изменить Капремонт»
  · «Внести УК» (запрашивает сумму и месяц)
· Кнопка «Назад» / «Главное меню».

Процесс изменения тарифа (кроме электричества):

1. Администратор нажимает кнопку, например, «Изменить тариф Воды».
2. Бот отправляет сообщение: «Текущий тариф на воду: 45.50 руб./куб.м. Введите новое значение (число, например 47.00) или нажмите "Отмена", чтобы оставить без изменений.»
3. К сообщению прикреплена кнопка «Отмена» (inline-кнопка).
4. Если администратор вводит число (в том числе 0) – тариф обновляется. Если нажимает «Отмена» – тариф остаётся прежним.
5. Подтверждение: «Тариф на воду обновлён: 0.00 руб./куб.м» (если был введён 0) или «Тариф не изменён».

Процесс изменения тарифа на электричество:

1. Администратор нажимает кнопку «Изменить тариф Электричества».
2. Бот показывает текущие значения:
   Текущий тариф на электричество:
   до 150 кВт·ч — 4.90 руб.
   от 150 до 800 кВт·ч — 6.21 руб.
   свыше 800 кВт·ч — 8.27 руб.
3. Бот предлагает ввести новые значения:
   Введите новые тарифы через пробел: порог1 тариф1 порог2 тариф2 тариф3
   Например: 150 4.90 800 6.21 8.27
   Если хотите единый тариф (без ступеней), введите одно число, например 5.50.
   Для отмены нажмите кнопку "Отмена".
4. Валидация: если введено 5 чисел, проверяется, что порог1 < порог2. Иначе бот просит повторить.
5. Подтверждение обновления.

Особенности:

· Для УК дополнительно запрашивается месяц (в формате ММ.ГГГГ) и сумма. Если УК за этот месяц уже внесена – бот предупреждает и предлагает перезаписать.
· Для капремонта – только сумма (применяется к текущему месяцу).
· Все тарифы могут быть равны 0, это корректное значение (бесплатная услуга).

3.3. Ежемесячный цикл сбора показаний

Расписание:

· Напоминание арендатору – 23-го числа каждого месяца в 10:00 (по московскому времени). Бот отправляет напоминание всем арендаторам (для каждой квартиры отдельно) с просьбой передать показания до 25-го числа.
· Повторное напоминание – если арендатор не сдал показания до 24-го числа, бот отправляет повторное напоминание 24-го числа в 10:00.
· Контрольная дата – 25-е число – последний день сдачи показаний.
· Уведомление администратору о несданных показаниях – 26-го числа в 10:00 бот отправляет администратору список квартир (и арендаторов), которые не передали показания за текущий месяц.

Последовательность опроса арендатора (строго по порядку):

1. Запрос показаний электричества (кВт·ч).
2. После корректного ввода – запрос показаний воды (куб.м).
3. После корректного ввода – запрос показаний газа (куб.м).

Валидация ввода:

· Только положительные числа (включая 0), можно с дробной частью (разделитель – точка).
· Если число меньше предыдущего показания для этого счётчика – бот просит повторить ввод с пояснением: «Новое показание не может быть меньше предыдущего (было 1200). Введите корректное значение.»
· Если число равно предыдущему – это допустимо (расход нулевой), бот принимает его и переходит к следующему шагу.

После ввода всех трёх показаний:

· Бот сохраняет показания в БД с привязкой к квартире и месяцу.
· Бот рассчитывает расход по каждому ресурсу:
  · Для электричества: по ступенчатой формуле (см. раздел 4).
  · Для воды и газа: (тек – пред) * тариф.
· Проверяет, внесена ли сумма УК за предыдущий месяц (например, для августа проверяет УК за июль).
  · Если внесена – включает её в итог.
  · Если нет – формирует итог без УК и отправляет арендатору сообщение: «Сумма УК за прошлый месяц пока не поступила. Итоговая сумма рассчитана без неё. Как только администратор добавит квитанцию, вы получите уведомление с обновлённой суммой.»
· Отправляет арендатору итоговое сообщение с разбивкой по категориям (см. раздел 6.1).
· Отправляет администратору детализированный отчёт (см. раздел 6.2) с чек-боксами для отметки оплаты по каждой услуге (включая капремонт, но капремонт виден только админу). В этом отчёте также указывается срок оплаты – до 10-го числа следующего месяца.

3.4. Уведомления о загрузке УК и квитанции

· Когда администратор вносит сумму УК за конкретный месяц (через кнопку «Внести УК»), бот:
  · Обновляет запись в БД.
  · Автоматически пересчитывает итоговую сумму для всех арендаторов этой квартиры за тот месяц, за который была внесена УК (если они уже сдали показания).
  · Отправляет каждому арендатору этой квартиры уведомление: «Администратор добавил сумму УК за июль 2026: 1200 руб. Обновлённая итоговая сумма за август 2026: X руб. (с учётом УК).» и полный пересчитанный отчёт.
· Если администратор загружает файл квитанции (фото или PDF) с подписью «Квитанция УК за июль 2026», бот пересылает этот файл всем арендаторам этой квартиры с текстом: «Администратор загрузил квитанцию УК за июль 2026.» (файл не сохраняется на сервере, просто пересылается через Telegram).

3.5. Отметка об оплате и напоминание администратору

· В отчёте, который получает администратор, под каждой строкой с суммой услуги (вода, электричество, газ, ТКО, УК, капремонт) есть инлайн-кнопка:
  · Если не оплачено: [ ] Оплатить
  · Если оплачено: [✔] Оплачено
· При нажатии на кнопку статус оплаты в БД меняется, и кнопка обновляется.
· Напоминание об оплате: 8-го числа каждого месяца в 10:00 бот проверяет все отчёты за предыдущий месяц (т.е. за месяц, который уже прошёл). Если по какой-либо квартире есть неоплаченные услуги (статус paid = False), бот отправляет администратору сообщение-напоминание с перечнем неоплаченных сумм и ссылкой на соответствующий отчёт (можно с кнопкой для быстрого перехода).
· История оплат сохраняется и отображается в /history.

3.6. Команды администратора (текстовые)

· /start – приветствие и главное меню.
· /help – вызов контекстной инструкции (см. раздел 7).
· /select_flat <номер> – выбор активной квартиры для настроек.
· /flats – список всех квартир с их тарифами.
· /addflat <название> – создание новой квартиры.
· /history – история расчётов для активной квартиры с фильтром по месяцу (можно запросить за конкретный месяц).
· /stats – текущие тарифы и последние показания для активной квартиры.
· /adduser, /removeuser, /listusers – управление доступом.
· /menu – главное меню (аналог /start).

3.7. Команды арендатора

· /start – приветствие и краткая информация.
· /help – инструкция для арендатора.
· Арендатор не имеет команд для изменения тарифов или просмотра истории других квартир.

4. Бизнес-правила (логика расчётов)

4.1. Расход ресурса

Расход = Тек_показание – Пред_показание (если равно 0 – допустимо).

4.2. Стоимость электричества (ступенчатый тариф)

Хранятся параметры для каждой квартиры: threshold1, tariff1, threshold2, tariff2, tariff3.

```
если consumption <= threshold1:
    sum = consumption * tariff1
иначе если consumption <= threshold2:
    sum = threshold1 * tariff1 + (consumption - threshold1) * tariff2
иначе:
    sum = threshold1 * tariff1 + (threshold2 - threshold1) * tariff2 + (consumption - threshold2) * tariff3
```

4.3. Стоимость воды и газа

Сумма = Расход * Тариф (тариф может быть 0).

4.4. Итог для арендатора

Итог = Сумма_воды + Сумма_электричества + Сумма_газа + ТКО + УК_за_предыдущий_месяц (если внесена)
Капремонт не включается.

4.5. Итог для администратора (в отчёте)

Тот же итог для арендатора + отдельная строка «Капремонт» (не включается в сумму арендатора).

4.6. Лаг УК

Всегда берётся сумма УК за месяц, предшествующий текущему расчётному. Например, для расчёта за август используется УК за июль. Если такая запись отсутствует – УК не добавляется, и арендатор получает уведомление об отсутствии.

4.7. Капремонт

Администратор может установить сумму на текущий месяц. Она не влияет на арендатора, но сохраняется в истории администратора.

4.8. Сроки

· Показания должны быть переданы до 25-го числа текущего месяца включительно.
· Оплата должна быть произведена до 10-го числа следующего месяца.
· Бот напоминает арендатору о передаче показаний 23-го и 24-го числа.
· Бот напоминает администратору об оплате 8-го числа следующего месяца, если есть неоплаченные счета.

5. Нефункциональные требования

· Доступность: 24/7. Хостинг – бесплатный облачный сервис, поддерживающий веб-воркеры (рекомендуется Render.com).
· Производительность: обработка сообщений < 2 сек.
· Безопасность: белый список Telegram ID, все запросы проверяются на наличие пользователя в БД.
· Хранение данных: SQLite (для MVP), с перспективой перехода на PostgreSQL. Все данные привязаны к flat_id.
· Масштабируемость: архитектура поддерживает добавление неограниченного числа квартир без изменения кода.
· Разработка: код пишется в Replit.com (или в среде по выбору) с использованием ИИ-агента, затем деплоится на продакшен-хостинг.
· Рекомендация: администратор должен устанавливать тарифы до начала расчётного месяца (до 23-го числа), чтобы расчёты выполнялись по актуальным значениям.

7. Инструкция для пользователей (текст команды /help)

Для арендатора:

📖 Инструкция для жильца

1. Как передать показания?

· Бот напоминает вам 23-го и 24-го числа каждого месяца.
· Показания нужно передать до 25-го числа.
· Отвечайте на вопросы по порядку: электричество → вода → газ.
· Вводите только числа (можно с точкой). Например: 1250 или 1250.5.
· Если ошиблись – бот попросит повторить.

2. Что происходит после ввода?

· Бот рассчитает сумму и покажет вам итог.
· Если администратор ещё не внёс УК за прошлый месяц, вы увидите сумму без УК и получите уведомление позже.
· Когда УК появится – бот пришлёт пересчитанный итог.

3. Квитанции

· Если администратор загрузит квитанцию УК, она придёт вам в этот чат.

4. Дополнительно

· Команда /start – показать приветствие.
· Команда /help – эта инструкция.

Пример:
Бот: «Введите показания электричества (кВт·ч):»
Вы: «1250»
Бот: «Принято. Теперь введите показания воды…»

Для администратора:

📖 Инструкция для администратора

1. Управление квартирами и пользователями

· /addflat <название> – создать новую квартиру (например, /addflat Квартира 2).
· /adduser <TelegramID> <role> <flat> – добавить пользователя (role: admin или tenant).
· /removeuser <TelegramID> – удалить.
· /listusers – список всех пользователей.
· /select_flat <номер> – выбрать активную квартиру для настроек.
· /flats – список всех квартир.

2. Настройка тарифов и платежей

· После выбора квартиры откройте меню командой /menu или через главное меню.
· Используйте кнопки для изменения тарифов. При вводе нового значения можно поставить 0 – это означает бесплатную услугу.
· Для электричества – введите 5 чисел через пробел (порог1 тариф1 порог2 тариф2 тариф3) или одно число для единого тарифа.
· Чтобы отменить изменение, нажмите кнопку «Отмена» – тариф останется прежним.

3. Внесение УК

· Нажмите кнопку «Внести УК», введите сумму и месяц (например, 07.2026).
· После внесения бот автоматически пересчитает итоги для всех арендаторов этой квартиры за соответствующий месяц и отправит им уведомление.

4. Загрузка квитанций

· Отправьте боту фото или PDF с подписью: «Квитанция УК за июль 2026». Бот перешлёт её всем арендаторам этой квартиры.

5. Отметка оплаты

· В отчётах под каждой суммой есть кнопка для отметки оплаты. Нажмите – и статус сохранится.
· Важно: оплатить нужно до 10-го числа следующего месяца. 8-го числа бот напомнит вам о неоплаченных счетах.

6. История

· /history – показать все расчёты по выбранной квартире с фильтром по месяцу.

Пример:
Чтобы добавить жильца в квартиру №2:
/adduser 123456789 tenant 2
Чтобы изменить тариф на воду: выберите квартиру /select_flat 2, затем в меню нажмите «Изменить тариф Воды» и введите новое число.

10. Критерии приёмки (как понять, что бот готов)

· Бот отправляет напоминание арендаторам 23-го и 24-го числа в 10:00 МСК.
· Если показания не сданы до 25-го числа, 26-го числа бот уведомляет администратора.
· Арендатор может последовательно ввести показания (электричество → вода → газ) с валидацией (равенство предыдущему разрешено).
· Бот корректно рассчитывает сумму для воды и газа по простому тарифу, для электричества – по ступенчатому.
· Администратор получает отчёт с чек-боксами для каждой услуги (включая капремонт) и указанием срока оплаты (до 10-го числа следующего месяца).
· Арендатор получает итоговую сумму без УК, если УК за прошлый месяц не внесена, и уведомление о появлении УК позже.
· При внесении УК бот пересчитывает итоги и уведомляет арендатора.
· 8-го числа каждого месяца бот отправляет администратору напоминание о неоплаченных счетах за предыдущий месяц.
· Администратор может через кнопки изменить любой тариф (включая установку 0) с отменой через кнопку «Отмена».
· Для электричества – можно ввести 5 чисел для ступенчатого тарифа или одно число для единого; проверяется порог1 < порог2.
· Администратор может создать новую квартиру, добавить/удалить пользователей.
· Только добавленные пользователи имеют доступ (белый список).
· Для разных квартир можно установить разные тарифы.
· История сохраняется и доступна по /history для администратора.
· Команда /help выдаёт корректную инструкцию в зависимости от роли пользователя.
